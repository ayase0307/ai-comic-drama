# 小說改編核心原則與保留分級（Adaptation Principles）

- **責任領域**：跨媒介轉碼理論、原著事件保留分級、A/B/C 改編方案設計、記帳式因果與退稿閘門。
- **理論來源**：Linda Hutcheon《A Theory of Adaptation》、Robert McKee《Story》、Syd Field《Screenplay》、蘆葦《電影編劇的秘密》、陸軍《編劇理論與技法》、`jtydhr88/screenwriting-skills`、`zenstory-ai/drama-skills`。

---

## 一、跨媒介轉碼定律（Transcoding Law）

1. **從「講述（Telling）」到「展示（Showing）」**：
   - 小說的核心優勢在於內在意識流與全知旁白；漫劇／影視的核心優勢在於**外部處境、可見行動與視聽對位**。
   - 忠於原著不是「保留原著每一段文字」，而是忠於原著的**戲核（Core Dramatic Premise）、核心因果鏈與人物靈魂（Integrity）**。
2. **加減乘除提煉故事脊椎（陸軍技法）**：
   - **減法**：砍除不推動主線因果的旁支人物、重複打怪／重複受辱與背景百科解說。
   - **加法**：當原著因旁白過多而缺乏視覺支點時，補入「做功道具（Working Prop）」與「時限壓力（Ticking Clock）」，並顯式標註 `【改編新增】`。
   - **合併（Merge）**：將功能重疊的 3 個配角合併為 1 個具鮮明記憶點的角色；將多次同質衝突合併為 1 場層次遞進的關鍵戰役。

## 二、原著故事單位保留分級（6-Tier Retention Grading）

在 Phase 3 分析原著時，必須對每個章節或事件單元賦予以下六種標籤之一：

| 分級代碼 | 定義與判定準則 | 處置要求 |
| :--- | :--- | :--- |
| **`MUST_KEEP`** | 一旦刪除將導致後續事件因果斷裂、主角核心弧線崩塌或失去原著最具辨識度的名場面。 | 100% 保留戲劇功能，並配置最佳視覺與時長預算。 |
| **`KEEP_IF_POSSIBLE`** | 具鮮明角色魅力、獨特世界觀風味或商業記憶點，但非主因果鏈唯一支點。 | 視目標集數與單集時長（±15%）決定獨立成場或融入主場景。 |
| **`MERGE`** | 與其他場景在「資訊揭露、人物關係推進、情緒極性」上功能重複。 | 與相鄰或同功能場景合併，遵循「一魚多吃（單場同時推進事件與關係）」。 |
| **`COMPRESS`** | 因果功能必要（如獲得關鍵物品、確立盟約），但原著過程冗長。 | 採用「晚進早出（Late In, Early Out）」或蒙太奇動作節拍壓縮至 10–20 秒。 |
| **`REMOVE`** | 純背景設定堆砌、無後續回收之廢棄支線、或與主線無關的過場。 | 刪除；若含微量必要資訊，必須在 `adaptation_diff` 說明如何轉移至其他場景交代。 |
| **`REORDER`** | 原著按時間順序平鋪直敘導致開篇慢熱，或原著插敘打亂觀眾理解。 | 調整呈現順序（如提取危機作為冷開場，或將背景拆為衝突中的自然揭示），須確保真實時間線不矛盾。 |

## 三、改編方案 A / B / C 決策矩陣（Phase 4 Checkpoint）

面對同一部小說，必須提供三種不同取向的方案供創作者／製片方決策：

1. **方案 A：忠於原著型（Canon-First）**
   - **策略**：最大化保留 `MUST_KEEP` 與 `KEEP_IF_POSSIBLE` 事件，維持原著敘事順序與慢熱鋪墊。
   - **優勢**：原著粉滿意度最高，世界觀與人物群像最豐滿。
   - **風險**：開篇前 3 集衝突密度可能偏低，總集數較長，場景與角色資產數量較多。
2. **方案 B：節奏與商業推進型（Pacing-First / Balanced）**
   - **策略**：積極使用 `MERGE`、`COMPRESS` 與 `REORDER`（如前置核心危機為冷開場），按單集 90–120 秒微容器重組節拍。
   - **優勢**：兼顧原著因果與短劇／漫劇完播率，集尾懸念明確。
   - **風險**：部分支線配角被合併，需妥善修補過渡因果。
3. **方案 C：AI 製作成本優先型（Feasibility-First / Bottle）**
   - **策略**：將多地點流轉壓縮至 1–3 個高復用主場景（Bottle Scenes），單場同框人數嚴格控制在 ≤ 2–3 人，將高風險多人大戰改寫為「蓄力對峙 + 意象快切 + 結果呈現」。
   - **優勢**：AI 生圖／I2V／FL2V 成片率最高，資產漂移與穿模風險最低，算力成本最省。
   - **風險**：視覺格局較內斂，需仰賴強對白潛台詞與道具特寫支撐張力。

## 四、記帳式累積因果（Debt Ledger）

為根治爽劇「每集反轉卻集集清零」的弊病，採用 `sw-series-engine-bible` 的記帳式因果：
- **單元事件可閉合，人物代價不閉合**：主角在第 $N$ 集解決了一個危機或動用了一張底牌，必須在帳本上登記一筆債務：`[debt_id] 第 N 集動用禁術/得罪勢力/隱瞞真相 → 預計第 M 集誰來討債/爆發後果`。
- 每集劇本必須至少「兌現一筆舊債」或「新增一筆具體未來集數的新債」。

## 五、四大一票否決退稿閘門（Hard Gatekeepers）

不論 100 分制總分多高，只要觸發以下任一閘門，劇本強制判定為 `FAIL (REVISE)`：

1. **`FATAL_CAUSAL_BREAK`**：重要決定、反殺或轉折缺乏前置動機或先決事件（例如：毫無鋪墊突然獲得神功秒殺強敵）。
2. **`CANON_CONTRADICTION`**：人物能力、性格底線、世界規則或連戲狀態（如已損毀的道具無故完好出現）自相矛盾。
3. **`CRITICAL_SCENE_UNFILMABLE`**：關鍵情節仍為不可拍攝的心理描寫（如「他心中百感交集，想起了三年前的往事」），或包含無替代方案的極高危 AI 崩壞動作。
4. **`UNTRACKED_MAJOR_CHANGE`**：對原著進行了刪除關鍵事件、合併主要角色或顛倒因果等實質修改，卻未在 `adaptation_diff` 中誠實記錄。

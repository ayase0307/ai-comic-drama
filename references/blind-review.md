# 盲審（fresh-eyes review）：只給材料、不給結論

- **責任領域**：階段 3 劇本定稿前、階段 7 交付前的獨立視角審核；材料包組法與盲審 agent 的提示詞模板。
- **來源依據**：Eian（@EianLu）2026-11-05 X 長文《Claude code/Codex+Seedance AI视频：从一个想法到成片的全流程》——「新開一個 agent 來審，只給故事，其他文件都不要給」。
- **工具**：`python scripts/build_blind_review.py --root <專案> --stage 3|7 [--episode EPxx] [--inputs 檔…]`

---

## 一、為什麼要盲審

主 agent 跟使用者聊了幾十輪，看自己的產物會自動腦補：劇本裡沒寫的動機它替角色補上了，分鏡裡含糊的走位它「知道」是什麼意思。**同一個 agent 審自己的稿，等於沒審。** 盲審的做法是開一個全新的 subagent，只給它材料本身（劇本本文／成片抽幀拼貼），不給任何結論——它看不懂的地方，就是觀眾會看不懂的地方。

本技能的確定性檢查（validate、audit、QA 腳本）抓「格式與物理」，盲審抓「敘事與理解」；兩層互補，缺一層都會漏。

## 二、什麼時候跑

| 時機 | 材料包 | 必要性 |
|---|---|---|
| 階段 3 劇本定稿前（每集） | `--stage 3`（只帶 `script-epXX.md`） | **必跑**；不通過先改稿 |
| 階段 7 交付前（每集） | `--stage 7`（核准版影片抽幀拼貼） | **必跑**；不通過先修 |
| 階段 1 故事地圖／大綱定稿前 | `--inputs <故事地圖等檔案>` | 選用；長篇改編建議跑 |

## 三、怎麼跑（五步）

1. **組材料包**：`python scripts/build_blind_review.py --root <專案> --stage 3 --episode EP01`。產出 `review/blind/stage3-ep01/`（劇本本文＋manifest.json）。**材料包裡不准出現任何結論**——verdicts、QA 報告、shot_intent、審核頁、adaptation-diff 一律不進包（腳本已保證；手動 `--inputs` 時自己把關）。
2. **開 fresh subagent**：新開一個 subagent（不是本對話的延續），只給它**材料包資料夾路徑**，明確告訴它「不准讀專案裡的其他檔案」。
3. **用下面的模板下指令**（按階段選一份）。
4. **收盲審報告**：把 subagent 的完整輸出存成 `review/blind/blind-review-stage3-ep01.md`（stage7 同理）。主 agent 不代寫、不改寫盲審結論。
5. **處置**：`不通過` → 逐條改稿／修片 → 重組材料包 → 重盲審；`通過` → 在該階段送使用者核准時附一句「盲審已過（`review/blind/…`）」。盲審報告是核准訊息的一部分，不是新門禁——不改 `h3d` 狀態機，`verdicts.json` 仍是階段 6 逐段結論的 SSoT。

### 階段 3 盲審模板（只給材料包路徑）

```text
這是〈專案名〉第 N 集的盲審材料：review/blind/stage3-ep01/。你第一次看，只負責挑錯，不改任何檔案，也不讀資料夾以外的任何東西。
1. 只按順序讀，先用 3–5 句寫出你看懂的故事。
2. 按順序追問每個轉折：為什麼會這樣？東西從哪來？夠得著嗎？現實裡真會這樣嗎？
3. 能用一句話說清這集想表達什麼嗎？
4. 開頭抓人嗎？最抓眼球的畫面放在前面了嗎？
5. 旁人的反應像真人嗎？反應有沒有先後？
每條寫：位置（場／句）、問題、建議改法。沒把握的寫「可能」。最後寫「通過」或「不通過」。
```

### 階段 7 盲審模板（只給材料包路徑）

```text
這是〈專案名〉第 N 集成片的盲審材料：review/blind/stage7-ep01/（每段一張抽幀拼貼，依段序命名）。你第一次看，不告訴你任何結論，只負責挑錯，不改任何檔案，也不讀資料夾以外的任何東西。
1. 先寫你看懂的故事，再列看不懂的地方。
2. 逐段查：重複的動作、道具數量、穿幫、突跳、顏色跳變、臉變形、畫面裡的字。
3. 明確寫出你查不了的東西（動態手感、聲音——拼貼沒有這兩樣）。
每條寫：段號、問題、建議。分「硬傷」和「小問題」。最後寫「通過」或「不通過」。
```

## 四、禁令

- 主 agent **不准**在材料包裡夾帶結論、提示或「這裡要注意什麼」。
- 盲審 agent **不准**讀材料包以外的專案檔案；它的結論只來自材料本身。
- 盲審 `不通過` 時**不准**跳過直接送使用者核准；逐條處置後重盲審。
- 盲審報告**不准**由主 agent 代寫或潤飾；原文存檔。

## 五、與既有流程的關係

- 這是**流程要求**，不是新門禁：`h3d next`／`build_stage_review` 的狀態機不變。
- 階段 6 的逐段 `h3d verdict` 照舊；盲審是階段 3／7 的敘事層複核。
- 盲審抓不到的（動態手感、聲音、逐幀技術 QA）仍由 `h3d qa`／`h3d motion`／`h3d qa --continuity` 與使用者人眼把關。

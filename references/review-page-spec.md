# 審查頁規格（決策收件匣優先）

交給使用者的審查頁只有一個：`review/inbox.html`（`h3d inbox --root .` 產生，程式在 `scripts/review/inbox.py`）。
舊的八個階段頁 `review/stage-N-*.html`（`build_stage_review.py --stage N`）降為**除錯頁**：它負責綁定審核快照與給 agent 對帳，不再是交給使用者的主頁。
例外是階段 0（定調）與階段 2（角色設定圖）：這兩關永遠要人親眼看設定與臉，舊頁保留作**附錄**，跟收件匣一起給。

為什麼：兩套頁面並行時，agent 不知道該交哪一頁；舊頁把 hash、全部 lint、完整 prompt 平鋪（階段 5 一頁超過 1 MB），使用者找不到真正要決定的事。

## 1. 什麼才算重要（上頂層的判準）

只有會造成下面三件事之一的，才能放進「需要你決定」或「真正擋關」：

1. **出片失敗**：送件會被拒、片子會壞（缺參考圖、時長漂移、混臉、燒字幕）。
2. **成本浪費**：會讓生成白跑（硬送必重跑的段、還沒定案就開始出圖）。
3. **劇情走樣**：觀眾看得出來的故事或角色錯誤（事件沒交代、臉或服裝錯、音色錯）。

其餘一律進「可略過警告」。

## 2. 固定版面順序

| 順序 | 區塊 | 規則 | 收件匣實作 |
|---|---|---|---|
| 1 | 一行進度 | 格式固定：`階段N/7・X件待決・卡在Y` | 頁首 `p.progress` |
| 2 | 需要你決定 | **0–5 張**卡，依 `blocking` 排序；超過 5 張時保留前 4 張，其餘併成一張合併卡 | `blocking ≤ 2` 的卡 |
| 3 | 真正擋關 | **最多 3 條**，同類合併（同一句問題只列一次，標「N 處」） | 收件匣：擋關卡標題清單；舊頁：`render_issues` |
| 4 | 可略過警告 | **整區收合**，摘要只顯示總數 | 收件匣：`blocking = 5` 的卡；舊頁：其餘門禁問題收進「其餘 N 條」 |
| 5 | 已決定／自動處理 | 兩區都收合 | 「你已經決定的」「我自動處理了 N 件事」 |
| 6 | 附錄 | **只放連結**，不內嵌；舊階段頁標「除錯用」 | 頁尾原始資料清單 |

## 3. 決策卡必備欄位

| 欄位 | 規則 | 收件匣欄位 |
|---|---|---|
| `question` | 一句話問題，**≤ 46 字** | `title`（超過自動截斷，`question` 同值） |
| `why_you` | 為什麼要你決定、會影響什麼 | `impact`（`why_you` 同值） |
| `options` | **2–3 個**，每個都附 `reply`（點了就複製回覆文字） | `options[].label`／`options[].reply` |
| `recommendation` | 建議，必須對應其中一個選項 | `recommendation`；對應的選項固定是 `options[0]`（頁面標「建議」），`recommended_option` 記其 label |
| `if_ignored` | 不回覆會怎樣 | `if_ignored`（每個產卡處都要寫實際後果，不只靠預設文字） |
| `blocking` | **只能是 0／1／2／5**：0 擋全部、1 擋下一步、2 擋本階段核准、5 不擋 | `blocking` |
| `source` | 資料出處（檔名＋欄位） | `source` |

`validate_model()`（`collect()` 之後執行）負責檢查：缺必備欄位直接報錯（是程式 bug）；選項超過 3 個只留前 3、不足 2 個補「先放著」；`blocking` 不合法就改成 2 或 5；這些修正都會列在 `problems`，`h3d inbox` 會印出來。使用者寫進 `verdicts.json` 的自訂選項不會讓收件匣當掉。

**核准卡綁快照**：「階段 N 等你核准」卡只在 `review_snapshot` 與目前產物一致時出現，回覆文字帶審核快照前 8 碼（例如 `階段 4：通過（審核快照 1a2b3c4d）`）。快照過期時改列一條註記，agent 先重跑 `build_stage_review.py --stage N` 重綁，不讓使用者回答一張必被 `--approve-stage` 拒絕的卡。

## 4. 禁止事項

- **不平鋪** QA 原始欄位或完整 prompt：完整 prompt 一律放在 `<details>` 裡（舊頁 `render_prompt` 預設收合）。
- **不得用文字把警告升級**：等級只看程式算出的 `blocking`，卡片文案、標題、顏色都不能自己寫「嚴重」「必須」來越級。
- **不得新增 `review/*.html`**：要給使用者看的新東西做成收件匣的卡，不另開頁面。
- **簽核清單不得重複 lint 項**：程式已經檢查並擋關的項目（章節齊不齊、台詞語速、罐頭句、缺圖、17 條自檢 PASS/FAIL）不再出現在舊頁簽核清單或 KPI；清單只留需要人眼判斷的事（臉、服裝、走位、表演）。

## 5. Agent 流程

1. 產物齊了：`build_stage_review.py --project-dir . --stage N`（綁審核快照、寫出除錯頁）。
2. `h3d inbox --root .` 產生 `review/inbox.html`，交給使用者並停下（階段 0／2 附上舊頁當附錄）。
3. 使用者回覆卡片文字後：核准用 `build_stage_review.py --project-dir . --approve-stage N --user-note "<原話>"`；定案、裁示、音色見 `references/tooling.md` §2.6。

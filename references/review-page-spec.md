# 審查頁規格（決策收件匣優先）

交給使用者的審查頁只有一個：`review/inbox.html`（`h3d inbox --root .` 產生，程式在 `scripts/review/inbox.py`）。
舊的八個階段頁 `review/stage-N-*.html`（`build_stage_review.py --stage N`）降為**除錯頁**：它負責綁定審核快照與給 agent 對帳，不再是交給使用者的主頁。
例外是階段 0（定調）與階段 2（角色設定圖）：這兩關永遠要人親眼看設定與臉，舊頁保留作**附錄**，跟收件匣一起給。

為什麼：兩套頁面並行時，agent 不知道該交哪一頁；舊頁把 hash、全部 lint、完整 prompt 平鋪（階段 5 一頁超過 1 MB），使用者找不到真正要決定的事。

## 1. 什麼才算重要（上頂層的判準）

只有會造成下面三件事之一的，才能放進「需要你決定」或「真正擋關」：

1. **出片失敗**：送件會被拒、片子會壞（缺參考圖、時長漂移、混臉、燒字幕）。
2. **成本浪費**：會讓生成白跑（硬送必重跑的段、還沒定案就開始出圖）。
3. **劇情走樣**：觀眾看得出來的故事或角色錯誤（事件沒交代、臉或服裝錯、音色錯）。

其餘一律進「可略過警告」。

## 2. 固定版面順序

| 順序 | 區塊 | 規則 | 收件匣實作 |
|---|---|---|---|
| 1 | 一行進度 | 格式固定：`階段N/7・X件待決・卡在Y` | 頁首 `p.progress` |
| 2 | 需要你決定 | **0–5 張**卡，依 `blocking` 排序；超過 5 張時保留前 4 張，其餘併成一張合併卡。合併卡必須保留每張子卡（`children`），頁內可逐件展開問題、選項與來源；頁首待決數計**原始件數**（`pending_total`），5 張只是首屏限制 | `blocking ≤ 2` 的卡 |
| 2a | 簽核牌組（呈現方式） | `blocking ≤ 2` 的卡做成牌組，一次一張：點選項＝簽下這張（蓋「已簽」章、卡片游走、換下一張），進度點可跳回任一張改答。最後一張之後是結尾頁：列出所有回覆，按「複製全部回覆」**複製成功才放慶祝動畫**，並明寫「貼回對話才算數」（簽核本身不會核准任何東西）。複製失敗時回覆會選取在文字框裡讓使用者手動複製。底部常駐「已簽 k 件・複製已簽回覆」，中途離開也帶得走。答案存在瀏覽器 `localStorage`，以作品名＋產生時間為鍵，重產收件匣就重新開始。沒有 JS 時所有卡照順序列出、點選項一樣複製。視覺沿用鯨工坊（亮色晴海潟湖／暗色深淵）與鯨魚娘吉祥物（`scripts/review/mascot/`；`--no-images` 時改用內嵌 SVG 鯨魚） | `scripts/review/inbox_page.py` |
| 3 | 真正擋關 | **最多 3 條**，同類合併（同一句問題只列一次，標「N 處」） | 收件匣：擋關卡標題清單；舊頁：`render_issues` |
| 4 | 可略過警告 | **整區收合**，摘要只顯示總數 | 收件匣：`blocking = 5` 的卡；舊頁：其餘門禁問題收進「其餘 N 條」 |
| 5 | 已決定／自動處理 | 兩區都收合 | 「你已經決定的」「我自動處理了 N 件事」 |
| 6 | 各階段成果 | 八個閱讀視圖，格式見 §6；首屏不展開，只開目前階段 | `#stage-0`–`#stage-7`（`scripts/review/stage_views.py`） |
| 7 | 附錄 | **只放連結**，不內嵌；舊階段頁標「除錯用」 | 頁尾原始資料清單 |

## 3. 決策卡必備欄位

| 欄位 | 規則 | 收件匣欄位 |
|---|---|---|
| `question` | 一句話問題，**≤ 46 字** | `title`（超過自動截斷，`question` 同值） |
| `why_you` | 為什麼要你決定、會影響什麼 | `impact`（`why_you` 同值） |
| `options` | **2–3 個**，每個都附 `reply`（點了就複製回覆文字） | `options[].label`／`options[].reply` |
| `recommendation` | 建議，必須對應其中一個選項 | `recommendation`；對應的選項固定是 `options[0]`（頁面標「建議」），`recommended_option` 記其 label |
| `if_ignored` | 不回覆會怎樣 | `if_ignored`（每個產卡處都要寫實際後果，不只靠預設文字） |
| `blocking` | **只能是 0／1／2／5**：0 擋全部、1 擋下一步、2 擋本階段核准、5 不擋 | `blocking` |
| `source` | 資料出處（檔名＋欄位） | `source` |

`validate_model()`（`collect()` 之後執行）負責檢查：缺必備欄位直接報錯（是程式 bug）；選項超過 3 個只留前 3、不足 2 個補「先放著」；`blocking` 不合法就改成 2 或 5；這些修正都會列在 `problems`，`h3d inbox` 會印出來。使用者寫進 `verdicts.json` 的自訂選項不會讓收件匣當掉。

**核准卡綁快照**：「階段 N 等你核准」卡只在 `review_snapshot` 與目前產物一致時出現，回覆文字帶審核快照前 8 碼（例如 `階段 4：通過（審核快照 1a2b3c4d）`）。快照過期時改列一條註記，agent 先重跑 `build_stage_review.py --stage N` 重綁，不讓使用者回答一張必被 `--approve-stage` 拒絕的卡。

## 4. 禁止事項

- **不平鋪** QA 原始欄位或完整 prompt：完整 prompt 一律放在 `<details>` 裡（舊頁 `render_prompt` 預設收合）。
- **不得用文字把警告升級**：等級只看程式算出的 `blocking`，卡片文案、標題、顏色都不能自己寫「嚴重」「必須」來越級。
- **不得新增 `review/*.html`**：要給使用者看的新東西做成收件匣的卡，不另開頁面。
- **簽核清單不得重複 lint 項**：程式已經檢查並擋關的項目（章節齊不齊、台詞語速、罐頭句、缺圖、17 條自檢 PASS/FAIL）不再出現在舊頁簽核清單或 KPI；清單只留需要人眼判斷的事（臉、服裝、走位、表演）。

## 5. Agent 流程

1. 產物齊了：`build_stage_review.py --project-dir . --stage N`（綁審核快照、寫出除錯頁）。
2. `h3d inbox --root .` 產生 `review/inbox.html`，交給使用者並停下（階段 0／2 附上舊頁當附錄）。
3. 使用者回覆卡片文字後：核准用 `build_stage_review.py --project-dir . --approve-stage N --user-note "<原話>"`；定案、裁示、音色見 `references/tooling.md` §2.6。

## 6. 八階段閱讀視圖（同一格式）

收件匣頁內每一關都有一個閱讀視圖（`#stage-N`，頁首階段圓點與「各階段成果」導覽都連得到）。使用者先看待決卡，要理解內容時點進對應階段讀完，再回來回覆。
視圖由 `h3d inbox` 每次從專案檔案重產，**Agent 不另外手寫階段報告**；要讓使用者讀到的內容，寫進該階段本來的產物（`project.md`、劇本、分鏡表…）。

每個視圖固定六區塊、固定順序：

| 順序 | 區塊 | 規則 |
|---|---|---|
| 1 | 進度列 | 階段名、狀態、更新時間、本關待決數。狀態只有六種：尚未產出／製作中／等你核准／已核准／內容已變更待重審／局部重審（階段 5：「N 段待你重審，M 段仍有效」）。製作狀態、技術 QA、正式核准分開，核准只信 `project_state`（`is_approved`、`stage5_segment_review`） |
| 2 | 需要你決定 | 本關的決策卡**只放連結**到上方的卡，不複製第二份 |
| 3 | 本次成果摘要 | 最多 3 個數字，必須帶單位或分母（「影片 12／14 段」）；沒有資料就不列，不編造 |
| 4 | 成果閱讀區 | 本關文件清單：中文名、路徑、更新時間、這份文件讓你看什麼；沒有的標「尚未產出」（灰色，不是警告）。有狀態卡（`references/document-standard.md`）的文件先顯示狀態卡，`.md`／`.csv` 全文排版後收合（Markdown 排成閱讀頁、劇本用劇本版型、CSV 排成表格，`scripts/review/doc_render.py`；單檔 24k 字、全頁 40 萬字上限，超過標「只顯示前段」）；同一類超過 6 個檔收成一列 |
| 5 | 問題與處理 | 程式門禁（`stage_validation_errors`）的原文，最多 3 條，其餘計數並指向除錯頁；已核准或尚未產出的關不跑 |
| 6 | 紀錄與附錄 | 本關定案與核准紀錄（最新 5 筆）、舊階段頁連結（標「除錯用」） |

每關開頭一句「要回答的問題」，順序與文案見 `stage_views.STAGE_GUIDE`：

| 階段 | 要回答的問題 | 主要文件 |
|---|---|---|
| 0 定調 | 這部作品要做成什麼樣子？ | `project.md`、`decisions.json` |
| 1 改編 | 保留了哪些故事？改了哪些地方？ | `adapt/character-bible.md`、段落架構、改編方案 |
| 2 設定圖 | 這是不是我想要的角色與世界？ | `assets.md`、設定圖、`reference-manifest.json` |
| 3 劇本 | 故事順不順？台詞對不對？節奏夠不夠？ | `script-ep*.md`、`adaptation-diff.md` |
| 4 分鏡 | 觀眾要看懂什麼？畫面做不做得到？ | `storyboard-ep*.md`、構圖圖、`layer2/` |
| 5 提示詞 | 要送出的是哪個版本？這次改了哪些段？ | `prompts-ep*.md`、`segments-ep*.json` |
| 6 影片 | 生成的影片符不符合這一鏡的要求？ | `videos/`、`qa-report.json`、`verdicts.json` |
| 7 配音剪輯 | 這部成片可以交付了嗎？ | `narration-ep*.md`、`final/` |

新增一關要讀的文件：在 `STAGE_GUIDE` 補一列（glob、中文名、讓你看什麼），不要另開頁面。
